# 自建同步采用单写者快照，不直接同步项目目录

2026-11-10。本 ADR 决定跨电脑同步的边界与实现方向。

## 背景

项目目录包含 SQLite（WAL）、LanceDB、知识库副本和临时文件，不适合用 Git、网盘或共享目录并发写入。现有项目会话租约只在本机主进程内生效，不能充当跨电脑的分布式锁。WebDAV 云备份已经能上传和恢复 `.ainovel` 快照，但恢复总是创建新副本，且没有写锁和版本比较。

需要在多台电脑之间交接同一部作品，同时避免两台电脑同时写坏项目。

## 决定

1. **同步单位是封存的 `.ainovel` 快照，不是运行中的项目目录。** 客户端用现有 `exportPortableProject` 生成快照，服务端只保存不可变归档；下载后走现有 `restorePortableProject` 恢复成新副本。
2. **单写者租约。** 每个远端项目同一时间只有一个写租约。租约带 TTL，可由持有者续期；其他客户端只能读或等待。服务端不合并项目数据库。
3. **乐观版本检查。** 上传必须带 `baseVersion`；只有等于当前 HEAD 才生成下一个版本，否则返回 `409 VERSION_CONFLICT`。每次上传记录 SHA-256、字节数、时间和来源项目 ID。
4. **独立自建服务，不依赖 GitHub/Gitee。** `sync-server/server.mjs` 使用 Node 内置模块和文件系统保存 `head.json` 与不可变归档，Bearer Token 认证，可 Docker 部署。生产网络必须由 TLS 反向代理保护；客户端只允许对回环、私网 IPv4 和 `.local` 使用明文 HTTP。服务端对上传流式落盘、限制并发上传/项目数/快照数，并按认证前后分桶限速；`/health` 也需要令牌。
5. **本机配置加密。** 服务地址和每个项目的远端绑定保存在全局数据目录；令牌通过 Electron `safeStorage` 加密。系统加密不可用时只保留在本次会话，重启后要求重新输入。
6. **下载总是恢复成新副本。** 恢复成功后登记最近项目，并把新项目绑定到同一个远端项目和所选版本；不替换当前打开的项目。若恢复成功但绑定保存失败，恢复出的数据仍是权威结果。
7. **绑定表示“从远端当前 HEAD 继续”。** 绑定前读取远端 HEAD，并把本地 `lastVersion` 设为该值；随后上传产生新版本。需要旧内容的客户端应先下载对应版本，而不是绑定后覆盖。
8. **分叉由作者选择一台电脑为准，不做内容合并。** 快照记录上传电脑的 hostname、父版本和是否强制覆盖。客户端发现本地绑定版本落后于远端 HEAD 时，列出本机与远端最新快照的电脑名；选择本机则携带 `force` 和作者看到的 HEAD 版本上传本机快照并覆盖 HEAD；若 HEAD 在确认后又被更新则返回冲突。选择远端则下载该版本为新副本，不改动当前作品。强制上传仍需要有效写租约，并保留双方父版本以便追溯。

## 兼容与后果

- 不改变现有本地项目格式、`exportPortableProject`/`restorePortableProject` 语义或 WebDAV 云备份；同步是新增的传输层。
- 没有自动合并。两台电脑分叉后只能下载其中一个版本，或手工合并正文后重新上传。
- 令牌是共享密钥，归档不是端到端加密，包含正文、配置和便携资产；服务端数据目录必须按私密数据保护。
- 服务端不保存运行中的 WAL、LanceDB 写入或未完成的生成；客户端必须先把项目封存成快照。
- 上传时客户端仍整体读入归档用于哈希和传输，服务端已改为流式落盘；下载在客户端流式写盘并限制 512 MiB。后续如需更大项目，再把上传也改为流式。
